1. What is MVC and Why Use It?

MVC stands for Model-View-Controller. It is a design pattern that splits your application into three separate parts, each with a clear job:

Model
 
View
 
Controller


Each has ONE job:
Model = Data + Database
View = HTML + Presentation
Controller = Decision Maker
Component Job Examples in This Project
Model Reads/writes data from the database. Contains business rules about data. Medicine.php, User.php, Sale.php
View Shows HTML to the user. Never queries the database directly. login.php, medicines/index.php, header.php
Controller Receives user requests, asks Models for data, picks which View to show. MedicineController.php, AuthController.php
Why MVC? Without MVC, your code becomes a tangled mess of HTML mixed with database queries. MVC keeps things organized: you can change the database without touching the HTML, or redesign the UI without breaking business logic.

4. How a Request Flows (End to End)

When a user types http://localhost/medistock/public/medicines in their browser, here is exactly what happens, step by step:

1

Apache Rewrites the URL

The .htaccess file says: "If the requested file doesn't physically exist, send it to index.php." Since /medicines is not a real file, Apache redirects to index.php.

# public/.htaccess
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.php [L]
2

index.php Boots the Application

The entry point does 5 things in order:

  1. Registers an autoloader (so PHP can find classes automatically)
  2. Starts the session
  3. Sets security headers
  4. Loads routes from routes/web.php
  5. Dispatches the request (matches URL to a route)
3

Router Matches the URL

The Router checks each registered route. It finds: $router->get('/medicines', 'MedicineController@index'). The URL matches, so it will call MedicineController::index().

4

Controller Handles the Request

MedicineController::index() runs. It checks if the user is logged in (Middleware), asks the Medicine model for data, and loads the view file.

5

Model Queries the Database

The controller calls $this->medicineModel->getFiltered(). The Model builds a SQL query, executes it through the Database class, and returns an array of medicines.

6

View Renders the HTML

The controller does require __DIR__ . '/../Views/medicines/index.php'. The view file loops through the medicines array and outputs HTML. The header and footer layouts are included automatically.

7

Response Sent to Browser

PHP sends the complete HTML page back to the user's browser. The user sees the medicines list.

Think of it like a restaurant: The Router is the host who seats you. The Controller is the waiter who takes your order. The Model is the kitchen that prepares the food. The View is the plate that presents the food to you.

6. The Entry Point (public/index.php)

Every request goes through one file: public/index.php. This is called the Front Controller Pattern.

// public/index.php (simplified)

// 1. AUTOLOADER - Maps class names to file paths
spl_autoload_register(function (string $class) {
    $prefixes = [
        'App\\'  => __DIR__ . '/../app/',    // App\Controllers\* -> app/Controllers/*
        'Core\\' => __DIR__ . '/../core/',   // Core\Router -> core/Router.php
    ];
    // ...finds the file and requires it
});

// 2. SESSION
session_start();

// 3. SECURITY HEADERS
header('X-Content-Type-Options: nosniff');
header('X-Frame-Options: DENY');

// 4. BASE URL
define('BASE_URL', rtrim(dirname($_SERVER['SCRIPT_NAME']), '/'));

// 5. LOAD ROUTES
require __DIR__ . '/../routes/web.php';  // Creates $router with all routes

// 6. DISPATCH
$uri = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
$router->dispatch($_SERVER['REQUEST_METHOD'], $uri);

How the Autoloader Works

Without an autoloader, you'd need require 'Router.php' at the top of every file. The autoloader says: "When PHP sees Core\Router, look for core/Router.php and load it automatically." This is a simplified version of PSR-4, the PHP standard for autoloading.

7. Routing — How URLs Map to Code

Defining Routes (routes/web.php)

// routes/web.php
$router = new \Core\Router();

$router->get('/medicines',              'MedicineController@index');
$router->get('/medicines/{id}',         'MedicineController@show');
$router->post('/medicines/store',       'MedicineController@store');

This creates 3 routes:

HTTP MethodURLController MethodPurpose
GET/medicinesMedicineController::index()List all medicines
GET/medicines/5MedicineController::show(5)View medicine #5
POST/medicines/storeMedicineController::store()Save a new medicine

How Parameters Work

When the Router sees /medicines/{id}, it converts it to a regex:

// Router::buildPattern() converts:
//   /medicines/{id}
// to:
//   #^/medicines/(?P<id>[^/]+)$#

// Then when /medicines/5 is requested:
//   preg_match extracts: $matches['id'] = '5'
//   Calls: MedicineController->show('5')

Route Types

  • $router->get(...) — Only matches GET requests (browser navigating to a page)
  • $router->post(...) — Only matches POST requests (form submissions)
  • $router->any(...) — Matches both GET and POST

8. Database Connection — Singleton Pattern

The Database class uses the Singleton Pattern — only ONE database connection can ever exist during a request.

// core/Database.php (simplified)
class Database
{
    private static ?self $instance = null;  // The one instance
    private \mysqli $connection;

    private function __construct()  // Private = can't do "new Database()"
    {
        $config = require __DIR__ . '/../config/database.php';
        $this->connection = new \mysqli(
            $config['host'],      // localhost
            $config['username'],  // root
            $config['password'],  // (empty)
            $config['database']   // medistock_mvc
        );
    }

    public static function getInstance(): self
    {
        if (self::$instance === null) {
            self::$instance = new self();  // Create only once
        }
        return self::$instance;
    }

    public function query(string $sql, array $params = [], string $types = ''): mixed
    {
        $stmt = $this->connection->prepare($sql);
        $stmt->bind_param($types, ...$params);  // Safe from SQL injection!
        $stmt->execute();
        return $stmt->get_result();
    }
}
Why Singleton? Without Singleton, every Model would create its own database connection. With 10 queries, you'd have 10 connections. Singleton ensures all Models share ONE connection, which is more efficient and prevents connection limits from being hit.

9. Controllers — The Business Logic

Controllers are the "middlemen." They receive user input, call Models for data, and load Views for output.

Example: MedicineController (simplified)

class MedicineController extends Controller
{
    private Medicine $medicineModel;

    public function __construct()
    {
        parent::__construct();
        $this->medicineModel = new Medicine();  // Create the model
    }

    // GET /medicines - List all medicines
    public function index(): void
    {
        Middleware::auth();  // Must be logged in

        $search = $this->query('search', '');
        $medicines = $this->medicineModel->getFiltered($search);  // Ask model for data

        require __DIR__ . '/../Views/medicines/index.php';  // Load the view
    }

    // POST /medicines/store - Save a new medicine
    public function store(): void
    {
        Middleware::auth();

        // 1. Validate CSRF token
        if (!$this->validateCsrf($this->input('csrf_token'))) {
            $this->setFlash('danger', 'Invalid request.');
            $this->redirect('/medicines/create');
        }

        // 2. Get and validate input
        $name = trim($this->input('name'));
        if (empty($name)) {
            $this->setFlash('danger', 'Name is required.');
            $this->redirect('/medicines/create');
        }

        // 3. Save to database via model
        $id = $this->medicineModel->create([
            'name' => $name,
            'quantity' => (int) $this->input('quantity'),
            // ... more fields
        ]);

        // 4. Set success message and redirect
        $this->setFlash('success', "Medicine added! (ID: {$id})");
        $this->redirect('/medicines');
    }
}

The PRG Pattern (Post-Redirect-Get)

PRG Pattern: After saving data via POST, always redirect to a GET page. This prevents duplicate form submissions if the user refreshes. Notice how store() ends with $this->redirect('/medicines').

10. Models — Talking to the Database

Models handle ALL database operations. They never output HTML. They return arrays and integers.

Base Model (core/Model.php)

The base Model gives you CRUD operations for free. Every model inherits these:

// You get these methods automatically:
$model->find(5);                    // SELECT * FROM table WHERE id = 5
$model->all();                      // SELECT * FROM table
$model->all(['is_active' => 1]);    // SELECT * FROM table WHERE is_active = 1
$model->create(['name' => 'X']);    // INSERT INTO table (name) VALUES ('X')
$model->update(5, ['name' => 'Y']);// UPDATE table SET name='Y' WHERE id=5
$model->delete(5);                  // DELETE FROM table WHERE id = 5
$model->count();                    // SELECT COUNT(*) FROM table
$model->exists(['name' => 'X']);    // Returns true/false

Custom Model: Medicine.php

class Medicine extends Model
{
    protected string $table = 'medicines';  // Which table?

    // Custom method: get medicines with category names, with search
    public function getFiltered(string $search, int $categoryId, int $limit, int $offset): array
    {
        $sql = "SELECT m.*, c.name AS category_name
                FROM medicines m
                JOIN categories c ON m.category_id = c.id
                WHERE m.is_active = 1
                AND m.name LIKE ?          -- prepared statement, safe!
                ORDER BY m.created_at DESC
                LIMIT ? OFFSET ?";

        return $this->db->fetchAll($sql, ['%' . $search . '%', $limit, $offset], 'sii');
    }

    // Custom: decrease stock atomically
    public function decreaseStock(int $id, int $quantity): bool
    {
        $this->db->query(
            "UPDATE medicines SET quantity = quantity - ?
             WHERE id = ? AND quantity >= ?",   -- prevents negative stock
            [$quantity, $id, $quantity],
            'iii'
        );
        return $this->db->affectedRows() > 0;
    }
}
SQL Injection Prevention: Notice every query uses ? placeholders and bind_param(). User input is NEVER concatenated directly into SQL strings. This makes SQL injection impossible.

12. Middleware — Authentication & Security

Middleware checks run BEFORE a controller method executes. They protect pages from unauthorized access.

// core/Middleware.php
class Middleware
{
    // Must be logged in
    public static function auth(): void
    {
        if (!isset($_SESSION['user_id'])) {
            header('Location: /login');
            exit;
        }
    }

    // Must have a specific role
    public static function role(string $requiredRole): void
    {
        self::auth();  // First check login
        if (($_SESSION['role'] ?? '') !== $requiredRole) {
            header('Location: /dashboard');
            exit;
        }
    }

    // Must be admin
    public static function admin(): void
    {
        self::role('admin');
    }

    // Must be logged OUT (for login page)
    public static function guest(): void
    {
        if (isset($_SESSION['user_id'])) {
            header('Location: /dashboard');
            exit;
        }
    }
}

How Controllers Use Middleware

// In any controller method:
public function index(): void
{
    Middleware::auth();        // Redirect to /login if not logged in
    // ... show page
}

public function store(): void
{
    Middleware::admin();       // Must be admin
    // ... delete user
}

public function showLogin(): void
{
    Middleware::guest();       // Redirect to /dashboard if already logged in
    // ... show login form
}

14. The Database Schema

The project uses MySQL with 8 tables. Here is the structure:

medistock_mvc database
│
├── users                    -- Login credentials, roles (admin/staff)
├── categories               -- Medicine types (Tablet, Syrup, etc.)
├── suppliers                -- Pharmaceutical suppliers
├── medicines                -- Core inventory (name, batch, expiry, qty, price)
│   ├── FK -> categories.id
│   └── FK -> suppliers.id
├── sales                    -- Sale records (INV-YYYYMMDD-NNNN format)
│   └── FK -> medicines.id
├── prescription_details     -- Doctor/prescription info for controlled drugs
│   └── FK -> sales.id (CASCADE delete)
├── stock_adjustments        -- Audit trail for stock changes
│   └── FK -> medicines.id
├── settings                 -- Key-value config (thresholds, pharmacy name)
└── audit_log                -- Security/compliance activity log

Key Relationships

  • Each medicine belongs to one category and one supplier (Foreign Keys)
  • Each sale links to one medicine
  • Prescription details cascade-delete with their sale (if sale is deleted, prescription is too)
  • Stock adjustments are permanent records for audit trail
  • Foreign key constraints prevent orphaned records (e.g., can't delete a category that has medicines)

Seed Data

The schema includes sample data for testing: 8 categories, 4 suppliers, 10 medicines, 1 admin user (admin/admin123), and 5 settings.

16. How to Create Your Own Project Like This

Here is a step-by-step guide to building your own MVC project from scratch:

Step 1: Set Up Your Environment

1

Install XAMPP (or Laragon for Windows). It includes Apache, MySQL, and PHP.

# Verify PHP and MySQL are running
php -v
mysql --version

Step 2: Create the Directory Structure

2
mkdir my_project
cd my_project
mkdir -p app/Controllers app/Models app/Views/layouts
mkdir -p core config database public/assets/css public/assets/js routes uploads

Step 3: Build the Core Framework

3

Start with these files in this order:

  1. config/database.php — Your MySQL credentials
  2. core/Database.php — Copy from this project (Singleton connection)
  3. core/Model.php — Copy the base CRUD class
  4. core/Router.php — Copy the URL matching engine
  5. core/Controller.php — Copy the base controller
  6. core/View.php — Copy the helper functions
  7. core/Middleware.php — Copy the auth checks

Step 4: Create the Entry Point

4

Create public/index.php and public/.htaccess exactly as in this project. These never change.

Step 5: Create the Database

5

Design your tables in MySQL. Start simple:

    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
